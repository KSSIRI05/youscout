# Contributing

Use short feature branches and pull requests reviewed by another team member. Link changes to requirement IDs or ADRs. Keep implementation instructions in the README accurate and use meaningful tests for authorization, persistence and distributed failure behavior.

For architecture changes, add or update a proposed ADR before implementation. Record assumptions explicitly; do not label proposals as assignment requirements or completed functionality. Never commit credentials, private user media or production data.

Before a pull request, run the implemented project's format, lint and relevant test commands. These commands will be documented when the code exists. Include what changed, why, validation performed and material limitations in the description.
